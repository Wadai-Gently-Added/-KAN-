# 換-KAN- 拡張子一括変換ツール v1.0.5

複数フォルダに存在する大量ファイルの「拡張子だけ」を、安全に一括変換するローカル完結ツール。
ファイルの中身は一切変換しない。

## 動作環境

- **対応：** Chrome / Edge（デスクトップ版のみ）
- **非対応：** Safari（macOS/iOS/iPadOS）、Firefox、モバイル版Chrome全般

File System Access API を使ってユーザー端末内のフォルダを直接読み書きしているため、
このAPIが実装されていないブラウザでは起動時に警告バナーが表示され、「フォルダ追加」が無効化される。

iPhone/iPadは仕組み上どうしても対応できない（iOSは全ブラウザがWebKit強制のため）。
デスクトップのChrome/Edgeで運用してほしい。

## 使い方

1. 「＋ フォルダ追加」でリネーム対象のフォルダを選ぶ（ブラウザのフォルダ選択ダイアログが開く）
2. 各フォルダで「対象」「サブフォルダを含める」「階層の深さ」を設定
3. 「＋ ルール追加」で `.ts → .txt` のような変換ルールを登録
4. 「プレビュー更新」を押して、変更予定の一覧を確認
5. 内容を確認して「実行」
6. 誤りがあれば「↶ Undo」で直前の変更を取り消し、「↷ Redo」でやり直し

## 内部動作の注意点

- リネームは OS のようなアトミックな rename ではなく、
  **新ファイル作成 → 書き込み → サイズ検証 → 旧ファイル削除** という手順で行っている
  （File System Access API に単一のrename命令が存在しないため）。
  途中で失敗した場合はその1件だけ「失敗」としてログに記録し、他のファイルの処理は継続する。
- 変更後の名前が既に存在する場合は **衝突あり** として自動的にスキップする。上書きはしない。
- Undo/Redoの履歴は**セッション中のみ有効**（ページを閉じると消える）。
  ブラウザの再起動をまたいだUndoはv1では未対応。
- 拡張子の大文字・小文字は区別せず判定する（`.TS` と `.ts` は同じ扱い）。
- **フォルダを削除・再作成する操作（Zipの再展開、フォルダの移動やリネームなど）をすると、
  登録済みのフォルダ参照が無効になる。** その場合はフォルダ一覧に「⚠ 再登録が必要」と表示されるので、
  一度削除してから「＋フォルダ追加」で選び直すこと。

## v1で対応していないこと（意図的に対象外）

- ファイル内容そのものの変換
- 正規表現によるファイル名変更
- ルールのプリセット保存・読み込み
- ブラウザ再起動をまたいだUndo/Redo
- iOS/Safari/Firefoxでの実行

これらは使用感を見てから検討する。

## 更新が反映されない時の対処

`sw.js`（Service Worker）が原因で、更新をGitHubに上げても古い画面のまま、ということが起こり得る。
v1.0.4でキャッシュ戦略自体は直したが、**既にブラウザに登録済みの古いService Worker**が残っていると
一度は手動でリセットする必要がある。

1. 対象ページをChrome/Edgeで開く
2. DevTools（F12）→「Application」タブ→左メニューの「Service Workers」
3. 表示されているワーカーの「Unregister」を押す
4. 同じくDevTools内の「Storage」→「Clear site data」も押しておくと確実
5. ページを再読み込み

以後は新しいキャッシュ戦略（ネットワーク優先）になるので、通常のブラウザの再読み込み（Ctrl+Shift+R / Cmd+Shift+R）だけで最新版が反映されるはず。

## GitHub Pages側の反映タイムラグ

Service Workerとは別に、GitHub Pages自体もCDNキャッシュがあるため、
コミット後すぐには反映されず**数十秒〜数分のタイムラグ**が出ることがある。
「変わってない」と思ったらまず1〜2分待ってから再読み込みしてみること。

## ローカルでの起動方法

`file://` で直接開くと File System Access API やService Workerの一部制約に当たることがあるため、
簡易サーバー経由での起動を推奨：

```bash
npx serve .
# または
python3 -m http.server 8000
```

ブラウザで `http://localhost:8000` を開く。
